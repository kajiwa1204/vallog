# ロードマップ

Vallog の開発ロードマップ。GitHub Projects（`@kajiwa1204's vallog project`）と連動し、各フェーズを Milestone で管理する。

> **前提**: `feat/prototype` ブランチは設計検証のためのプロトタイプ（使い捨て）。本実装は本ロードマップに沿って別スケジュールで進める。プロトタイプで得た知見は Phase 2 以降の Issue として記録済み。

> **最終締め切り: 2026-08-24（月・U-22プログラミングコンテスト作品提出）。本番デプロイ済み（外部公開・審査員が触れる状態）が提出条件。** 逆算で Phase 1（コア機能）を 2026-08-10 までに完成、2026-08-17 に機能凍結し、残り1週間（8/17〜8/24）を本番デプロイ・デモ動画・Protopedia投稿と予備日に充てる。
>
> ※ 当初は「最終締め切り8/31・Phase 1を7/25」としていたが、実際のU-22提出締切が8/24（デプロイ必須）と確定したため全フェーズを前倒しで再設定した。7/25時点でPhase 1は未達。

- GitHub OAuth認証（バックエンド / フロントエンド） — #6, #7
- OAuthセットアップウィザード（資格情報の暗号化保存・画面から設定） — #35
- プロジェクトCRUD + 招待リンク + UI — #8, #9
- GitHubデータ取得・TTLキャッシュ・スコア計算 — #10, #11, #12
- **変化ログ（第1層・AIなし土台）** — #77（既存キャッシュから時系列一覧＋一次リンク。ダッシュボード/メンバー詳細/分配の骨格。AIが落ちても機能する）
- ダッシュボード / メンバー詳細画面 — #13, #14（変化ログを主役・スコアを副次に）
- 貢献サマリー基盤（第2層・変化ログの詳細。プロトタイプ知見を反映した本実装） — #30, #34, #31, #32, #33, #16
  - #30 LLMプロバイダ抽象化（Claude / OpenAI互換 / Ollama）
  - #34 diffベースPR要約（lockファイル除外・head_shaキャッシュ判定）

  - #33 PR単位の個別サマリー生成・強制再生成（事後の手動オンデマンドのみ）
  - #16 貢献サマリー表示（画面5・7。変化ログの詳細として展開・根拠リンク併記）

### クリティカルパスと所要見込み
スコア計算(#12)・GitHubデータ取得(#10/#11)・AIサマリー基盤(#30〜#34)・認証/プロジェクト系はバックエンド実装済み。**残りのMVPは主要4画面のフロントが丸ごと未実装＋分配API(#17)＋変化ログ(#77)** で、実働 ≈ 27〜42h。

**貢献可視化の土台は変化ログ（#77・AIなし）** で、`#12` 完了済みのため即着手可能・AIサマリー基盤に依存しない。ダッシュボード/メンバー詳細/分配の各画面（#13/#14/#18）は #77 を骨格として先に成立し、AIサマリー（第2層・#16）は後から乗る。したがって**AIサマリー表示 #16 はクリティカルパスから外れ**、遅延・障害があっても第1層の可視化は動く。

着手順（8/10完成の逆算）:
1. **今週（〜7/27）BE**: #77 変化ログ（全画面の変化ログを解錠・2〜4h）→ #17 分配API（#18を解錠・4〜6h）
2. **〜8/10 FE**: #13 ダッシュボード → #14 メンバー詳細 → #18 分配画面（変化ログ主役・スコア副次で実装）
3. **余裕があれば**: #16 AIサマリー表示（クリティカルパス外・削り候補）

2バックエンド + 1〜2フロントエンドの並走を前提。詰まった場合は #16・テスト網羅を Post-submission に回して第1層＋分配で提出する。
