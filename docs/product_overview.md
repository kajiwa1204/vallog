# Vallog — プロダクト概要

## ビジョン

有志開発チームでの新規プロダクト創出を最大化する。

## ミッション

チーム開発の貢献を客観データで可視化し、正しく報いるインフラを作る。

## バリュー

| バリュー | 意味 |
|---|---|
| 透明性 | GitHubへの直リンク、編集履歴の全員公開。根拠を隠さない。 |
| 客観性 | 定量・定性データを判断の材料にする。主観やAIにすべてを委ねず、チームが根拠を持って合意できるようにする。 |
| チームの自律 | システムは提案のみ。評価・分配の決定はチームが行う。 |

---

## プロダクト概要

| 項目 | 内容 |
|---|---|
| プロダクト名 | Vallog |
| 対象ユーザー | GitHubを中心に動く3〜8人の有志開発チーム（ハッカソン・副業・学生チームなど） |
| 解決する課題 | チーム開発の個人貢献が不透明で、客観的な証明・評価が難しい |
| 提供価値 | 貢献の可視化・記録（変化ログ＋スコア。就活アピール、チーム内透明性）＋ 報酬・賞金が発生した場合は分配シミュレーションも行える |

> **ターゲットを絞る理由**: 会社組織には既存の評価インフラ（OKR・人事評価）がある。有志開発チームはそれがなく、かつ報酬変動が発生しうる唯一のセグメント。ここがブルーオーシャン。

---

## 設計思想

- **「AIが評価を決めない」設計**
  スコアリング・分配・変化ログ（第1層）はAIを使わない。AIは貢献サマリー（変化ログの詳細化）にのみ用いる、クリティカルパス外の機能に留める。評価・分配の決定はチームが行う。

- **客観データを根拠にした合意形成**
  GitHubの客観データをベースに、分配の合意プロセスをサポートする。

- **分配はオプション**
  賞金・報酬が発生しないチームでも、貢献の可視化・証明として使える。分配を行うかどうかはチームが設定する。

## MVPスコープ

### 対象機能

| # | 機能ブロック | 内容 |
|---|---|---|
| A | GitHubデータ取得・スコア算出 | Issue/PR/レビュー/TAT/SPラベル |
| B | 貢献の可視化（変化ログ＋スコア） | 変化ログ（誰がどのPR/Issueを・時系列＋GitHub一次リンク）を主役に、スコアを副次で提示。AIなし（第1層・土台） |
| C | 分配シミュレーション | 重みカスタマイズ＋複数案の比較 |
| D | 貢献サマリー生成 | 変化ログの詳細をClaude APIで要約（第2層・根拠リンク併記）。メンバーごとの貢献を文章で記録 |

> **Feature DはAIの唯一の用途。** スコアリング・分配・変化ログ（第1層）はAIを使わず、AIは貢献の「証明・記録」の詳細化にのみ使う。**AIはクリティカルパス外**で、AIが落ちても第1層（変化ログ・スコア）は機能する。詳細は `docs/scoring_design.md`「変化ログと貢献サマリー」を参照。

### Post-MVP

| フェーズ | 機能 |
|---|---|
| Post-MVP ① | Discordログを加えた貢献サマリーの強化（Discord API + Claude API） |
| Post-MVP ② | 実際のログ表示 |
| Post-MVP ③ | Slack連携 |
| Post-MVP ④ | 期間フィルター |
| Post-MVP ⑤ | リアルタイム更新（WebSocket） |

### データ更新方式

- **オンデマンド取得**（リロード時に最新データを取得して再描画）
- リアルタイム更新（WebSocket）はMVP対象外
