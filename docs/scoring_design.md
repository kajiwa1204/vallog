# Vallog — スコアリング設計

## カテゴリ構成

| カテゴリ | 種別 | デフォルト重み |
|---|---|---|
| GitHub活動量 | スコア対象 | 40% |
| タスク完了スピード | スコア対象 | 35% |
| 品質・可用性 | スコア対象 | 25% |

> 重みはチームごとにカスタマイズ可能

---

## 各カテゴリの指標

### GitHub活動量（40%）

| 指標 | 詳細 |
|---|---|
| Issue / PR 立ち上げ数 | 設計・デザイン・リファクタへの関与も含む |
| コードレビュー貢献 | コメント1件以上のレビューのみカウント |
| Approve / Request changes 回数 | 自分のPRへのセルフレビューは除外する |
| ターンアラウンドタイム | PR到着からレビューまでの時間。自分のPRへのセルフレビューは除外する |

カテゴリ内の合成: **均等割り**（後から調整可）

> 均等割りの4指標のうち3つ（レビュー貢献・Approve/Changes・TAT）はレビュー系のため、カテゴリ内は実質「起票 25% : レビュー 75%」の配分になる。MVPはこのまま運用し、実データを見て調整を判断する。

---

### タスク完了スピード（35%）

| 項目 | 詳細 |
|---|---|
| 計測式 | メンバー単位の 総獲得SP ÷ 総経過時間（タスク分割数に中立にするため、Issueごとの速度を足し上げない） |
| SP入力方法 | GitHub IssuesのラベルでSPを設定（例: `SP:1` / `SP:2` / `SP:3` / `SP:5` / `SP:8`）|
| 計測区間 | アサインからIssueクローズまで（PRマージによる自動クローズを想定）。Issue↔PRの紐付けはキャッシュに持たないため、クローズ時刻をマージ時刻の代理とする |
| 帰属 | Issueのアサイン先に帰属する。アサインのないIssueはSPが誰にも計上されない。PR↔Issue紐付けやクローズ実行者には依存しない |
| 前提 | **GitHub Projects運用**を必須とする |

- **Issueに紐付かないPR**はスピード評価の対象外（SPラベルはIssueにしか付かないため測定不能）。該当作業は活動量・品質カテゴリで評価される。
- **`state_reason`**: `not_planned`（着手せず却下・重複等）でクローズされたIssueはSPを計上しない。`completed`（手動クローズ・PRマージによる自動クローズ）のみ対象。
- **アサイン時刻の代替**: `/issues/events` の取得上限で `assigned_at` が得られない場合はIssue作成時刻を起点にフォールバックする（獲得SPを捨てないため）。
- **経過時間の下限**: アサイン直後クローズによる巨大値を防ぐため 0.1h でクランプする。

---

### 品質・可用性（25%）

| 指標 | 詳細 |
|---|---|
| 機能ごとの可用性スコア | 実装者以外のメンバーがレビュー・検証（他者にApproveされたマージ済みPR数を代理指標とする。セルフApproveは除外） |
| 手戻り率 | **PR再オープン回数のみ**で計測（PR作者に帰属）。設計上は「バグ報告数 + PR再オープン回数」だが、バグ報告を正しい原因者に帰属させる手段がキャッシュに無いため、MVPは再オープンのみとする。バグ報告数の帰属方式は #75 で設計する |

---

## スコア正規化

各指標の相対スコア = メンバー個人の値 ÷ チーム全体の合計値

> 例）チームのPR合計20件のうちAさんが5件 → Aさんの相対スコア = 5/20 = 0.25

この方式により、チーム規模や活動量に依存せず、メンバー間の相対的な貢献度を公平に比較できる。

---

## 分配シミュレーション

- 各メンバーの分配比率 = 総合スコア ÷ チーム全体の総合スコア合計（AIは使用しない）
- チームはまず貢献サマリー（Feature D）を読んで議論し、スコアは補助情報として参照する
- 最終的な分配の決定はチームが行う

---

## 貢献サマリー

> スコアリングとは独立した機能。AIの唯一の用途。

GitHubのコミット・PR内容をClaude APIで要約し、メンバーごとの貢献を文章で記録する。スコアの根拠補完および就活・実績証明としての利用を想定。

| フェーズ | データソース | 内容 |
|---|---|---|
| MVP | GitHubコミット・PR | メンバーごとの貢献サマリーを生成 |
| Post-MVP | GitHub + Discordログ | 議論・意思決定の文脈も含めたサマリーに強化 |
