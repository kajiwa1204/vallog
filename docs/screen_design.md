# Vallog — 画面設計

## 画面一覧

| # | 画面名 | 役割 | MVP |
|---|---|---|---|
| 1 | ログイン | GitHub OAuth認証 | ✅ |
| 2 | プロジェクト一覧 | 参加中プロジェクトの一覧・新規登録 | ✅ |
| 3 | プロジェクト設定 | リポジトリ確認・メンバー確認・重み設定・招待リンク発行 | ✅ |
| 4 | ダッシュボード | メンバー別スコア一覧 | ✅ |
| 5 | メンバー詳細 | カテゴリ別スコア内訳・貢献サマリー | ✅ |
| 6 | コミュニケーション詳細 | Discordの定量データ | Post-MVP |
| 7 | 分配シミュレーション | 重み調整・複数案の比較・合意 | ✅ |

## 画面遷移の設計方針

- メンバー詳細（5）はダッシュボード（4）からの遷移
- コミュニケーション詳細（6）はPost-MVP対象のためMVPでは非表示

## プロジェクト参加方式

- **招待リンク方式**を採用
- フロー: プロジェクト作成 → 招待リンク発行 → メンバーがリンクを踏む → GitHub OAuthでログイン → 参加完了
- GitHub Organization連携は不採用（有志開発チームへの課金負担を避けるため）

## プロジェクト管理

- 1ユーザーが複数プロジェクトに参加可能（Slackのワークスペースモデル）

## 画面別機能要件

### 画面1: ログイン

| 項目 | 内容 |
|---|---|
| 認証方式 | GitHub OAuth のみ |
| ログイン後の遷移 | プロジェクト一覧（画面2） |
| 招待リンク経由の場合 | ログイン後に該当プロジェクトへ自動遷移 |
| ゲストログイン | なし |

---

### 画面2: プロジェクト一覧

| 項目 | 内容 |
|---|---|
| 表示情報 | プロジェクト名・リポジトリ名・メンバー数 |
| 新規登録 | この画面からGitHubリポジトリを選択してVallogプロジェクトとして登録 |
| 登録後の遷移 | プロジェクト設定画面（画面3）へ遷移 |

> **注意**: 新規プロジェクト作成 = 既存GitHubリポジトリをVallogに登録すること。リポジトリ作成はGitHub側で行う。

---

### 画面3: プロジェクト設定

| 項目 | 内容 |
|---|---|
| リポジトリ | 登録済みGitHubリポジトリの確認 |
| メンバー | GitHubのコントリビューターを自動取得して表示 |
| カテゴリ重み | デフォルト値（40/35/25）で初期設定・後から変更可能 |
| 招待リンク | この画面から発行（メンバーがVallogにログインしてスコアを確認できる状態にするためのオンボーディング用リンク） |

---

### 画面4: ダッシュボード

| 項目 | 内容 |
|---|---|
| メンバー別総合スコア | 棒グラフで表示 |
| カテゴリ別スコア内訳 | 円グラフで表示 |
| 期間フィルター | なし（全期間表示・Post-MVPで追加） |
| 遷移先 | メンバー詳細（画面5） |

---

### 画面5: メンバー詳細

| 項目 | 内容 |
|---|---|
| カテゴリ別スコア内訳 | 各カテゴリのスコアを表示 |
| 各指標の生データ | PR件数・レビュー数などの具体的な数値 |
| 時系列グラフ | 活動量の推移 |
| 貢献サマリー | GitHubコミット・PR内容をClaude APIで要約したテキスト（Feature D） |
| GitHubへの直リンク | 該当PR/Issueへのリンク（根拠の透明化） |
| 他メンバーとの比較 | なし（Post-MVP） |

---

### 画面6: コミュニケーション詳細（Post-MVP）

| 項目 | 内容 |
|---|---|
| データソース | Discord / Slack（Post-MVP ③） |
| 表示内容 | メンバー別の発言数・リアクション数 |
| 表示内容 | チャンネル別の活動量 |
| AIによる要約 | Discordログ + GitHubの統合サマリー（Post-MVP） |

---

### 画面7: 分配シミュレーション

| 項目 | 内容 |
|---|---|
| 貢献サマリーの表示 | 各メンバーの貢献サマリー（Feature D）を画面上部に大きく表示 |
| スコアの参照 | GitHubスコアを画面下部に小さく表示（補助情報として配置） |
| 手動調整 | メンバー全員が数値を自由に編集できる。調整時に理由の入力を必須とする |
| 編集履歴 | 誰がいつ何を変更したか・その理由をタイムライン表示・全員に公開 |
| 重みの調整 | この画面上でその場で調整・複数案を比較 |
| 報酬総額の入力 | 任意入力（未入力時は貢献度の割合のみ表示） |
| 合意の記録 | チームで確定した分配案をVallog上に永続化 |

> **不正操作への対策**: 全員に編集履歴が公開されることで社会的抑止力を担保。承認制は過剰設計として不採用。
